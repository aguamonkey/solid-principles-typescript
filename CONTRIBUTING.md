# Contributing

Keep each change tied to a concrete learning pressure. State the consumer promise and explain an alternative before adding an abstraction.

Run `npm ci`, `npm run check`, install Chromium with `npx playwright install chromium`, then run `npm run test:browser`. Do not weaken production lint rules to accommodate an intentionally coupled Before example; scoped teaching exceptions belong only to those files.

Use real browser screenshots after verifying the relevant behaviour. Do not use mockups as evidence of implemented screens. Record meaningful limitations and keep exercises separate from their solutions.

Prefer explicit composition and idiomatic TypeScript. Do not introduce service containers, class hierarchies or a runtime code execution system without a demonstrated learning requirement.
